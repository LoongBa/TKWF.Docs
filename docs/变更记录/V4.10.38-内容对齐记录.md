## 变更背景

`_TKWF` 自 v4.10.37（2026-09-29）以来发布 **v4.10.38**（2026-09-30，本次唯一版本）：

- **v4.10.38**（2026-09-30）：**EntityUpdateBatchAsync 游离实体批量更新失败修复（ADR83，XiaoShuTong 问题单 G15）**——`DomainDataServiceBase.EntityUpdateBatchAsync` 对 `EntitySelectAsync`/`EntityGetAsync` 返回的游离实体批量更新抛"数据未被跟踪"异常（FreeSql `DbSet.UpdateRange` 校验仓储跟踪字典失败）；**根治**：`FreeSqlEntityDAC.UpdateBatchAsync` 改 SetSource 裸 IUpdate 路径（对齐 `UpdateColumnsBatchAsync`，不传 `UpdateColumns` = 按主键全实体更新，经 `uowManager.Orm` 保留 UoW 事务绑定，公共 API 签名零变化）；验证 18/18 Tier 1.5 全绿 + slnx 全量 0 错误 0 警告；API 参考文档批量更新行补注前置行为。**范围外观察项**：单条 `UpdateAsync` 的 N+1 回查挂载开销保留（另立决策）

**扩展侧**（`_TKWF.Extensions`，2026-09-30 批量落地）：

- **Authentication V0.1.0**（认证中心，`TKWF.Ext.Authentication`）——通用认证组件：令牌体系（手写 RS256 JWT + kid 轮换 + 黑名单落库 + Refresh rotation + TokenVersion 闭环）/ 认证矩阵 Provider（短信 + 微信双形态）/ 登录保护（频控）/ 票据换令牌（PKCE + redirect_uri 白名单）/ 身份适配层（`JwtDomainUserParser`/`ITokenVerifier`/`IAuthorizationMapper`/`AuthenticationUserHelperBase`/`JwtAuthenticationMiddleware`——**AuthorityFilter 零改动**）/ 跨系统映射 / 平台凭证（AES-GCM + WeChatApiClient）；8 实体 SG1 + 51 测试全绿 + 全量 30 项目零回归；Oracle 代码审核 PASS WITH CONDITIONS（4 MAJOR + 6 MINOR 全部闭环）+ Oracle3 复核 PASS
- **UserCenter V0.1.0**（用户中心，`TKWF.Ext.UserCenter` + `.Abstractions`）——通用档案面扩展：**契约包**（三 Source 抽象 `IUserProfileSource`/`IRedemptionHistorySource`/`IUserAppsSource` + 门面接口 + 3 DTO，零框架依赖）+ **主包零实体零存储**（门面组合三 Source + `PhoneMasker` 脱敏 + 过渡期模板基类）——机制优势发挥实证（扩展内自定义对象→三钩子装配消费方 DI/DomainHost）；Oracle 双评审 PASS WITH CONDITIONS + 实施 27/27 全绿
- **Account V0.3.1 → V0.4.0** + **SecurityLog V0.2.1 → V0.3.0**（契约拆包，ADR48 D7 第 5 次落地）——Account → SecurityLog 跨扩展直接引用债清偿：新建 `TKWF.Ext.SecurityLog.Abstractions`（11 公开契约 git mv 迁入，命名空间保持 `TKWF.Ext.SecurityLog` 零破坏）；Account 切 Abstractions + NoWarn 整块删除（L2 门控恢复全域硬约束）
